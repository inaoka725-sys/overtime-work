### 未確定：サーバー `gemini` の機種（2026/08/06 打合せで最初に潰す）

```powershell
$r=([adsisearcher]'(&(objectCategory=computer)(cn=gemini))').FindOne()
if($r){$r.Properties['operatingsystem']}else{'ドメイン未参加'}

Resolve-DnsName -Type SRV "_ldap._tcp.dc._msdcs.$env:USERDNSDOMAIN" | Select-Object NameTarget

certutil
```

### セキュアコンテキストの確保方式（AD CS の有無で決める）

https が必要な理由は2つだけ。台帳の自動読込（`showOpenFilePicker` — index.html:745,808 と
`navigator.storage.persist` — 812）と、管理者モード（`crypto.subtle.digest` — 929、
`isSecureContext` — 944）。他の機能（Excel出力・CSV・バックアップ・手動インポート）は
http でも動く。

| | ① 証明書で https | ② Chrome ポリシーで http 許可 |
|---|---|---|
| 採用条件 | **社内に AD CS エンタープライズCA がある** | **CA が無い** |
| サーバー側 | IIS → サイト(443) → 証明書の発行とバインド | IIS → サイト(80) のみ |
| クライアント側 | ルート証明書は AD から自動配布（作業ゼロ） | GPO で `OverrideSecurityRestrictionsOnInsecureOrigin` に `http://gemini` を1行 |
| 更新運用 | サーバー証明書の期限ごとに更新が必要 | なし |
| ブラウザ | 問わない | Chrome/Edge のみ（**Edge にも同じポリシーを配ること**） |

②の検証結果（Chrome 147 で実測。再検証不要）
- `http://gemini`（80番）＋ポリシー値 `http://gemini` で `isSecureContext=true`。crypto.subtle も実動作
- **非標準ポートを使うならポートまで完全一致で書く**（`http://gemini:8080`）。省略すると効かない
- ドット無しの単一ラベル名にワイルドカードは使えない（`*.gemini` は無効として無視される）
- W3C Secure Contexts 仕様 §7.2 が明示的に認めた仕組み。Chrome 69 から現役
- `dynamic_refresh: false` — **Chrome を完全終了しないと反映されない**
- **HTTP を流れるのはアプリの HTML/JS だけ**。勤務データ・単価は LocalStorage、台帳は SMB 経由

①の注意
- `gemini` のような社内名にパブリックCAは発行できない（CA/B Forum が2015年に禁止）
- 単一ラベル名の証明書は Chrome で有効。ただし **SAN の dNSName 必須**（CN は見ない）。
  SAN には `gemini` と `gemini.<ADドメイン>` の両方を入れる
- **正式URLは FQDN を推奨**。単語1つの入力は Chrome が検索クエリ扱いするため `https://gemini/` と
  末尾スラッシュが必要になる

### 設置作業の想定（サーバーが Windows Server だった場合・実作業1〜2時間）

1. ファイルを置く（overtime フォルダ、約1.5MB）2. IIS を有効化（**既定の役割のままでよい**。
Microsoft も静的サイトには既定構成で足りると明記。Directory Browsing だけ無効化する）
3. サイトを追加（物理パス＝1）4. 上表①または②の方式でセキュアコンテキストを確保
5. ファイアウォールで該当ポートを許可 6. 社内PCから動作確認

- 新しいDNS名は**不要**（サーバー既存のホスト名で足りる）
- `index.html` は IIS の既定ドキュメントに最初から含まれるため設定不要
- vendor は相対パス（`./vendor/...`）でサブディレクトリ配置に耐える。ただし
  **`xlsx.bundle.js` は SRI 付き**なので、転送でファイルが1バイトでも変わると Excel 出力が全滅する。
  バイナリ転送であることを確認すること
- 方式B（サーバー側から台帳を配信）を採れば台帳読込は http でも可能だが、**管理者モードは方式Bでも
  セキュアコンテキストが必須**。方式Bへの切替は新規約60行・削除約170行（index.html:697-699 に
  移行方法をコメント済み）

### 台帳連携について確定した仕様（2026/08/05 コード確認）

- **期の切替（35期→36期）はアプリの改修不要**。ファイル名を一切見ておらず、シート名「台帳」・
  ヘッダー行「ｵｰﾀﾞｰ」・列名の部分一致で判定している（index.html:651,657-663）。

  「台帳に再接続」ボタン1クリックで済む。Chrome 122 以降は「毎回許可」を選べば `granted` のまま

  管理共有（`C$`・`ADMIN$` 等）のみ。ドライブレター割当でも判定は同一
- 台帳の更新検知は60秒ポーリング＋`visibilitychange`。ほぼ毎日の追記運用に対応できる
- **未検証**：他ユーザーが Excel で台帳を開いている最中に読めるか。Chrome 側は
  `FILE_SHARE_READ|WRITE|DELETE` で開くためロックはしない（Chromium のコードで確認済み）が、
  Excel 側の共有モード次第。失敗する場合は `NotReadableError` として現れる

## アーキテクチャ

```yaml
構成: 単一HTMLファイル（サーバーレス）
ファイル:
  - index.html      # メインアプリ（HTML + CSS + JS 一体）
  - manual.html     # 操作マニュアル
  - overtime/docs/requirements.md     # 要件定義書
  - overtime/docs/SCOPE_PROGRESS.md   # 本ファイル
外部ライブラリ（vendor/ に同梱済み。外部通信なし）:
  - vendor/xlsx.full.min.js  — 読込用（window.XLSX_READ、SheetJS 0.20.3）
  - vendor/xlsx.bundle.js    — 書出用（window.XLSX、xlsx-js-style 0.18.5・SRI付き）
データ保存:
  - LocalStorage  — 作業データ / 設定 / オーダーマスター / 台帳メタ情報
```
