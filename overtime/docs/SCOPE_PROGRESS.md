### セキュアコンテキストの確保方式（② Chrome ポリシーで決着）

https が必要な理由は2つだけ。台帳の自動読込（`showOpenFilePicker` と
`navigator.storage.persist`）と、管理者モード（`crypto.subtle.digest` / `isSecureContext`）。
他の機能（Excel出力・CSV・バックアップ・手動インポート）は http でも動く。

**① 証明書で https にする案は検討終了**（TeraStation に HTTPS の設定項目が無いため成立しない）。
AD CS の有無は未確認のままだが、確認する必要がなくなった。

② の検証結果（Chrome 147 で実測。再検証不要）
- `http://gemini`（80番）＋ポリシー値 `http://gemini` で `isSecureContext=true`。crypto.subtle も実動作
- **非標準ポートを使うならポートまで完全一致で書く**（`http://gemini:8081`）。省略すると効かない
- **末尾スラッシュは有無どちらでもよい**（`GURL` のパス部は `url::Origin::Create()` で捨てられる。
  Chrome 公式のポリシー定義の例自体が `http://testserver.example.com/` と末尾スラッシュ付き）。
  2026/08/06 版の手順書に「末尾スラッシュは誤り」と書いたのは誤り。20260825 版で訂正した
- **スキーム（`http://`）を省略すると、その行はエラーも出さずに丸ごと無視される**
  （opaque origin として破棄。`is_potentially_trustworthy.cc` の `CanonicalizeAllowlist`）
- ドット無しの単一ラベル名は**スキーム＋ポート付きなら有効**（公式ドキュメントに明記は無いが
  Chromium のソースとテストデータで確認）。ワイルドカード形式では表現できない
- **http のまま https へ自動アップグレードされる心配はない**。このポリシーは HTTPS-Upgrades の
  除外リストとしても機能し（`https_upgrades_interceptor.cc`）、単一ラベル名は元々対象外
- `showOpenFilePicker` はセキュアコンテキスト以外に **「トップレベル」「非サンドボックス」
  「transient user activation（クリック等）の中で呼ぶ」** が仕様・実装ともに必須条件。
  本アプリはボタンの onclick から呼んでいるため条件を満たす
- ドット無しの単一ラベル名にワイルドカードは使えない（`*.gemini` は無効として無視される）
- W3C Secure Contexts 仕様 §7.2 が明示的に認めた仕組み。Chrome 69 から現役
- `dynamic_refresh: false` — **Chrome を完全終了しないと反映されない**
- **HTTP を流れるのはアプリの HTML/JS だけ**。勤務データ・単価は LocalStorage、台帳は SMB 経由

### 台帳連携について確定した仕様（2026/08/05 コード確認）

- **期の切替（35期→36期）はアプリの改修不要**。ファイル名を一切見ておらず、シート名「台帳」・
  ヘッダー行「ｵｰﾀﾞｰ」・列名の部分一致で判定している（index.html:651,657-663）。
  ただしハンドルは特定ファイルを指すため、**年1回、利用者が台帳を選び直す操作が必要**
- 再訪時はファイル選択不要。IndexedDB からハンドルを復元（850-865）。権限が落ちていても
  「台帳に再接続」ボタン1クリックで済む。Chrome 122 以降は「毎回許可」を選べば `granted` のまま
- UNC パス（`\\gemini\himalaya\...`）は選択可。Chromium がブロックするのは localhost と
  管理共有（`C$`・`ADMIN$` 等）のみ。ドライブレター割当でも判定は同一
- 台帳の更新検知は60秒ポーリング＋`visibilitychange`。ほぼ毎日の追記運用に対応できる
- **未検証**：他ユーザーが Excel で台帳を開いている最中に読めるか。Chrome 側は
  `FILE_SHARE_READ|WRITE|DELETE` で開くためロックはしない（Chromium のコードで確認済み）が、
  Excel 側の共有モード次第。失敗する場合は `NotReadableError` として現れる
- **`NotReadableError` の主因は「ロック」より「snapshot 不一致」の可能性が高い**（2026/08/25 調査）。
  `getFile()` は取得時点の mtime/size を snapshot として持ち、読み取り時に検証する
  （`local_file_stream_reader.cc` の `VerifySnapshotTime`）。取得後に Excel が上書き保存すると
  `ERR_UPLOAD_FILE_CHANGED` になり、Chromium は `ERR_FILE_NOT_FOUND` 以外の net エラーを
  すべて `NotReadableError` に潰す（`file_reader_loader.cc`）。**対策として、読む直前に必ず
  `getFile()` を取り直し、`NotReadableError` のときは1秒待って1度だけ再試行する**（実装済み）
- **再訪時の権限は既定で `prompt` に戻る**。IndexedDB から復元したハンドルは
  「a handle retrieved from IndexedDB is also likely to return "prompt"」（WICG 仕様）。
  Chrome 122 以降の3択で **「毎回のアクセスを許可」を選べば `granted` が保持される**
  （extended permission。ブラウザ再起動後も維持）。利用者への案内をアプリとマニュアルに追加済み。
  なお **エンタープライズポリシーでファイル権限を事前付与することはできない**
  （`FileSystemReadAskForUrls` 等の enum は Block / Ask のみで Allow が存在しない）
- `navigator.storage.persist()` はファイル権限を守るものではなく、**IndexedDB 自体が
  ストレージ逼迫で消えるのを防ぐ**もの。ハンドルの器を守るのが persist、権限を守るのが
  extended permission で、両方必要
