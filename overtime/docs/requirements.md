# 要件定義書 — 旬報（時間外・旅費精算書アプリ）

最終更新: 2026年7月28日

---

## 1. プロジェクト概要

### 成果目標
社員が1回入力するだけで、規程に準拠した残業時間・深夜作業手当の自動計算と、旬報（旅費交通費等精算書）の両方を出力できる。

### アプリ名称
2026年7月28日に、アプリ名を **「旬報」** に変更（`<title>` とヘッダー h1）。
タブ名は従来どおり「残業報告書 / 旬報 / 設定」の3タブ。

### 旬の呼称
社内呼称に合わせ、**一旬（1〜10日）／二旬（11〜20日）／三旬（21〜末日）** に統一（2026年7月28日）。
日付判定ロジック（`getJun()`）は従来のまま変更していない。

### 成功指標

**定量的指標**
- 残業手当の計算ミスをゼロにする
- 報告書作成時間を 5分以内 に短縮
- 残業報告書と旬報の二重入力を解消（1回入力で両方出力）

**定性的指標**
- 規程（時間外手当基準）に完全準拠した計算が行われる
- 現場・社内どちらの作業区分にも対応できる
- 旅費・日当の記録から旬報Excelを自動生成できる
- 報告者が計算方法を知らなくても正しい手当額を把握できる

### 運用前提（2026年7月28日時点で確定）

| 前提 | 内容 | 設計への影響 |
|------|------|-------------|
| 端末 | 従業員は1人1台・個人Windowsアカウント | LocalStorage に他人のデータが混ざるリスクがない |
| 労務原価 | 経理・管理部門が旬報上で記入する運用 | 従業員端末に勤務原価単価を置く必要がない（管理者モードの根拠） |
| 宿泊費 | 会社が予約・精算する | 従業員の入力は不要。旬報Excelの出力対象外 |
| オーダー台帳 | Windows Server 上に置かれている | 共有フォルダのファイルを直接参照する方式（File System Access API） |
| ネットワーク | 社内PCはインターネット接続可 | 現時点では CDN からライブラリを取得できる |
| クラウド利用 | 元請けからクラウド禁止の指示あり | 社内サーバーへの移行を計画中（下記） |

**社内サーバー移行時の必須対応（未実施・重要）**
現在 Excel ライブラリを CDN から取得している。社内サーバー（インターネット非接続を想定）へ移行する際は、
**ライブラリをアプリに同梱する**必要がある。同梱しないまま移行すると Excel の読込・出力がすべて機能しなくなる。

## 2. 規程準拠ルール

出典: `時間外手当基準（原紙）.xlsx`

### 残業開始時間
- **常用（平日）**: 勤務開始時間から **9時間30分後** から時間外手当を支給
- **休出（休日）**: 勤務開始時間から全時間が残業対象
- **有給・代休**: 残業計算なし

### 休憩時間（規程定義）

| 時間帯 | 休憩 |
|--------|------|
| 08:30 〜 09:00 | 0.5h |
| 12:00 〜 13:00 | 1.0h |
| 15:00 〜 15:30 | 0.5h |
| 18:00 〜 18:30 | 0.5h |
| 22:00 〜 22:30 | 0.5h |
| 02:00 〜 03:00 | 1.0h |
| 06:00 〜 06:30 | 0.5h |

### 時間外手当の種別

| 種別 | 時間帯 | 金額 |
|------|--------|------|
| 普通残業手当 | 残業時間のうち 6:00〜22:00 | 給与計算による |
| 深夜残業手当 | 残業時間のうち 22:00〜翌6:00 | 給与計算による |
| 深夜作業手当 | 18:00〜翌6:00 の常用勤務が5時間以上の場合 | **一律 3,000円** |

**注意事項（規程より）**
- 深夜作業手当と同時間帯の時間外作業手当は重複して支給しない
- 時間外時間は 0.5時間単位で集計（四捨五入）

## 3. システム全体像

### アーキテクチャ
```yaml
構成: 単一HTMLファイル（サーバーレス・インストール不要）
ホスティング: GitHub Pages（社内サーバーへの移行を計画中）
外部ライブラリ（2枚差し）:
  読込用: SheetJS xlsx-latest via CDN  → window.XLSX_READ（.xls / .xlsx 台帳の解析）
  書出用: xlsx-js-style@1.2.0 via CDN  → window.XLSX（罫線・塗り等のスタイル対応）
データ保存: ブラウザ LocalStorage / IndexedDB（サーバー送信なし）
```

読込用の SheetJS を先に読み込んで `window.XLSX_READ` に退避し、その後 xlsx-js-style が `window.XLSX` を上書きする。
書出はスタイル対応が必須、読込は最新版の .xls 解析が必要なため、両方を用途別に使い分けている。

## 5. 計算ロジック詳細

### 残業時間算出

```
勤務区分が有給・代休の場合: 残業 = 0（計算スキップ）

overtimeStart（常用）= 勤務開始時刻 + 570分（9時間30分）
overtimeStart（休出）= 勤務開始時刻

普通残業 = 残業時間帯 ∩ [6:00, 22:00] の実働時間（休憩除く）
深夜残業 = 残業時間帯 ∩ [22:00, 翌6:00] の実働時間（休憩除く）
```

### 帰社後作業の残業起点

```
常用: 本作業の overtimeStart（勤務開始 + 570分）をそのまま帰社後作業に適用する
休出: 帰社後作業自身の開始時刻を残業起点とする（休出は全時間が残業対象のため）
```

休出で本作業の起点を流用すると帰社後分が二重に丸められ、残業時間が過大になる。
2026年6月13日にこの分岐を修正した。

### 深夜作業手当

```
常用勤務の深夜時間帯在籍 = [勤務開始, overtimeStart] ∩ [18:00, 翌6:00] の実働時間
深夜作業手当 = 常用勤務の深夜時間帯在籍 ≥ 300分（5時間）? 3,000円 : 0円
休出の場合は常に 0円
```

### 時間の丸め

0.5時間単位（四捨五入）: `Math.round(minutes / 30) * 0.5`

### 交通費

往復選択時: 入力金額 × 2 で登録

### 旬の判定

```
1〜10日  → 一旬（upper）
11〜20日 → 二旬（mid）
21〜末日 → 三旬（lower）
```
三旬の末日は月の実日数から算出する（`new Date(y, m, 0).getDate()`）。


### 台帳連携の保存領域

| 保存先 | キー | 内容 |
|--------|------|------|
| IndexedDB | `overtime_ledger` / `handles` / `orderLedger` | 台帳ファイルのハンドル |
| LocalStorage | `overtime_ledger_meta` | 最終取込時の mtime・size・ファイル名・件数 |
| sessionStorage | `overtime_admin_unlocked` | 管理者モード解錠フラグ（タブを閉じると失効） |

### バックアップJSON

```yaml
format: "overtime-backup"
version: 1
exportedAt: ISO8601
entries: [ ... ]              # 作業データ全件
settings: { name, empNo, dept }
```

- **オーダーマスターは含めない**（台帳が真実の源であり、連携または再インポートで復元できるため）
- **勤務原価単価（costRate）は含めない**（管理者端末のバックアップを従業員が復元すると秘匿の前提が崩れるため）
- 復元は全置換。形式・バージョン・作業データの有無を検証し、不正なら理由を明示して中止する（握り潰さない）
- ファイル名: `旬報バックアップ_氏名_YYYYMMDD.json`

## 7. セキュリティ要件

- 静的ファイル配布のため、サーバーサイドセキュリティ要件なし
- 入力値はブラウザ内のみで処理し、外部送信しない
- Excel ライブラリを CDN から取得している（オフライン利用・社内サーバー移行時は同梱が必要）
- 書出用ライブラリ（xlsx-js-style）は SRI（integrity 属性）付きで読み込む

### 勤務原価単価の管理者限定（設計判断）

`?admin=1` で開いたときのみ PIN を尋ね、一致すればセッション中だけ設定欄を開放する。

**これはセキュリティ機能ではない。**
PIN は DevTools・LocalStorage の直接編集・sessionStorage の書換えで容易に迂回でき、
単価そのものは暗号化されず平文で LocalStorage に入る（SHA-256 は入力照合にしか使っていない）。
さらに旬報Excelに労務原価が印字されれば「労務原価 ÷ 日数」で単価を逆算できる。

したがって**守れている根拠は「従業員端末に単価を置かないこと」だけ**である。

- 一般URLでは設定の単価欄を表示しない（DOMに値も載せない）
- 一般端末では画面のオーダー別集計に勤務原価列を出さない
- 一般端末が出力した旬報Excelの労務原価は空欄になる（0円と印字しない）
- 労務原価は経理・管理部門が旬報上で記入する運用のため、そもそも従業員端末に単価が要らない

PIN は誤操作防止と目隠しにすぎない。初期PINは `index.html` のコメントに記載しており、
**運用開始時に必ず変更する**（変更手順もコメントに記載）。管理者モードは https:// でのみ利用できる
（`crypto.subtle` が secure context を要求するため）。

## 10. Excel出力仕様

### 共通（印刷設定）

`ws['!pageSetup']` は無効なため、**生成後の xlsx バイナリに後から注入する**方式を採る
（`injectPageSetup()`。CFB で各 `xl/worksheets/sheetN.xml` を書き換える）。

- 用紙: A4（paperSize=9）・**横向き**
- `fitToPage="1"` / `fitToWidth="1"` / `fitToHeight="1"` → 1枚に収める
- 水平中央寄せ、余白 左右0.31 / 上下0.39
- フォントは `ＭＳ Ｐゴシック`（未指定だと Calibri になるため必ず付与する）
- 生成に失敗した場合はアラートで通知して中止する（無反応にしない）

### 残業報告書（帳票シート）— 1旬＝1枚

**氏名 × 旬** でシートを分割する（「全期間」を選ぶと3旬×人数分のシートができる）。

- 行1: タイトル「時間外作業報告書」／右側に「確 認 欄」
- 行2〜5: **押印枠4個**（確認欄の下、太罫で囲む）
- 行7: 期間（例: 令和8年7月 三旬（7/21〜7/31））／報告者氏名（2列結合・折返し）／社員番号
- 行9: 見出し（区分・勤務区分・日付・オーダー №・件名・作業開始・作業終了・普通残業(H)・深夜残業(H)・深夜作業手当(円)）
- 行10〜: 明細。**最低15行**の枠を確保。帰社後作業は「帰社後作業」区分の別行
- 末尾: 合計行（普通残業H・深夜残業H・深夜作業手当）
- シート名: `氏名_旬ラベル`（禁止文字は `_` に置換、重複時は連番）

### 残業報告書（一覧シート）

- 全対象者の明細一覧（日付・報告者氏名・社員番号・区分・勤務区分・オーダー №・件名・開始・終了・普通残業H・深夜残業H・深夜作業手当）
- 合計行つき。シート名は「一覧」

### 残業報告書CSV

- BOM付きUTF-8・CRLF・全項目をダブルクォートで囲む（Excelで開いても文字化けしない）
- 列は一覧シートと同構成。帰社後作業は別行
- ファイル名: `残業報告書_令和○年○月○旬.csv`

### 旬報（旅費交通費等精算書シート）— 会社原本の書式

**氏名 × 旬** でシートを分割する。

**ヘッダー（行1〜5）**
- 表題「旅費交通費等精算書」／「○月度分」
- 所属・社員NO.・氏名（右側、見出しはピンク塗り）
- 期間「YYYY/M/D から YYYY/M/D まで」（旬の実日付。三旬の末日は月の実日数）

**明細（12列・行7〜8が2段見出し）**

| # | 列 | 内容 |
|---|-----|------|
| 1 | 日付 | M/D |
| 2 | オーダ番号 | |
| 3 | 工事名 | 左寄せ |
| 4 | 常用 | 該当なら 1 |
| 5 | 休出 | 該当なら 1（原本どおり灰色塗り） |
| 6 | 有給 | 該当なら 1 |
| 7 | 代休 | 該当なら 1 |
| 8 | 勤務時間 自 | 常用・休出のみ印字（有給・代休は空欄） |
| 9 | 勤務時間 至 | 同上 |
| 10 | 日当 | 円 |
| 11 | 交通費 | 円 |
| 12 | 小計 | **日当 ＋ 交通費**（宿泊費は出力対象外のため含めない） |

- 明細は**最低15行**の枠を確保
- 合計行: 常用・休出・有給・代休の**日数（件数）**、日当計・交通費計・小計計
- 宿泊費・交通機関・区間・備考が入力されているエントリーがある場合、出力前に
  「出力対象外である」旨を明示して確認する

**オーダ別集計ブロック**

| 列 | 値 |
|----|-----|
| ｵｰﾀﾞ番号 | エントリーのオーダー番号（未入力は「（なし）」） |
| 日数 | **常用・休出の日付ユニーク数**（同日複数エントリーでも1日、有給・代休は除外） |
| 部 | **7**（原本の固定値） |
| 品名 | **旅費交通費**（原本の固定値） |
| 借方 | **540525**（原本の固定値） |
| 貸方 | 空欄（原本どおり記入者が埋める） |
| 金額 | そのオーダーの小計合計（日当＋交通費） |
| 労務原価 | 日数 × 勤務原価単価。**単価未設定なら空欄**（0円と印字しない） |

- 最低9行の枠を確保し、末尾に合計行

**注記・フッター（原本の文言そのまま）**
```
注）①当月1日～10日、11日～20日、21日～末日までの３旬毎で清算する。
    ②1日2件以上の交通機関を利用した場合は、行をかえて詳細に記載する。
    ③各旬締め日より３日以内かつ月末は締め日翌日（１３日、２３日、翌月１日）に提出すること。
```
末尾に「株式会社 神戸エーアイテレコム」を印字。

### ファイル名

- 残業報告書: `時間外作業報告書_令和○年○月○旬.xlsx`
- 残業報告書CSV: `残業報告書_令和○年○月○旬.csv`
- 旬報: `旬報_令和○年○月○旬_氏名.xlsx`
- バックアップ: `旬報バックアップ_氏名_YYYYMMDD.json`

令和年号は `getFullYear() - 2018` で算出する。

## 11. オーダー台帳連携

### 解析仕様（手動インポート・自動反映で共通 = `parseOrderWorkbook`）

- シート: 名前に「台帳」を含むシートを優先し、無ければ先頭シート
- ヘッダー行: 先頭20行以内で「ｵｰﾀﾞｰ」または「オーダー」を含む行を自動検出
- 列の自動マッピング: オーダー（必須）／件名・工事／担当／日当
- オーダー番号が数値セルの場合は整数文字列へ変換し、空・0 の行は読み飛ばす
- 取込はマスターの**全置換**（差分マージではない）
- ヘッダー行やデータが見つからない場合はエラーを投げて理由を表示する
- 実績: オーダー台帳から **2,993件** の取込を確認（2026年5月27日）

### 自動反映（File System Access API）

- 共有フォルダ上の台帳ファイルのハンドルを IndexedDB に永続化する
- 起動時・**画面復帰時（visibilitychange）**・**60秒ごと**に `lastModified` / `size` を確認し、
  **変化があったときだけ**再解析する
- 起動時は権限要求ができないため `queryPermission` のみ。未許可なら「台帳に再接続」を促す
- 台帳が移動・削除された、共有フォルダに接続できない等は理由を画面に表示する（隠さない）
- **Chrome / Edge 限定**。未対応ブラウザでは手動インポートを最初から開いた状態にしてフォールバックする
- 取込処理の出口は `applyOrderWorkbook()` の1か所に集約してある。
  社内サーバー（IIS）配信へ移行する際は `fetch('./data/オーダー台帳.xls')` の ArrayBuffer を
  ここへ渡すだけでよい

## 12. 提出フロー（業務）

**残業報告書**
```
報告者が入力・Excel出力
  ↓
直近上司 確認・承認
  ↓
所属部長 承認
  ↓
事務 受理
```
提出期限: 各旬報〆日から3営業日以内

**旬報（旅費交通費等精算書）**
```
報告者が入力・Excel出力（残業報告書と同時）
  ↓
上長 確認・承認
  ↓
事務 受理・精算処理（労務原価は経理・管理部門が記入）
```
提出期限（原本注記③）: 各旬締め日より3日以内、かつ月末は締め日翌日（13日・23日・翌月1日）
